# AI-Assisted Monument Decay Annotation Pipeline

**System:** Heritage AI Decay Monitoring and Preservation Recommendation System  
**Module:** `ai/annotation_assistant`  
**Target Architecture:** SSD (Single Shot MultiBox Detector)  
**Status:** **ANNOTATION READY — HUMAN ANNOTATION REQUIRED**

---

## 1. Why AI-Assisted Annotation is Being Used

Manual bounding-box labeling across hundreds of multi-megapixel ($3072 \times 4096$) ancient temple photos is time-consuming, repetitive, and prone to fatigue. The AI Annotation Assistant automates candidate region extraction to accelerate human review.

> **CRITICAL DISTINCTION:**
> - **AI Proposal:** A candidate suggestion generated by image-processing / computer vision heuristics (color saliency, ridge filtering, dampness contrast). Marked `REVIEW_REQUIRED`. **Never treated as ground truth.**
> - **Human-Verified Annotation:** An annotation that has been inspected, edited, or confirmed by a human reviewer and exported as valid Pascal VOC XML. **Only verified annotations become ground truth.**

---

## 2. Model & Methods Used for Proposal Generation

Because general vision models (like standard COCO object detectors) are trained on everyday objects (cars, persons, chairs) rather than ancient granite masonry decay, using an off-the-shelf detector directly would generate irrelevant labels.

Instead, the proposal pipeline employs **specialized heritage computer vision heuristics**:
1. **Moss Proposals:** Green-excess color saliency index ($2G - R - B$) and chromaticity ratio filtering to identify biological lichen, bryophyte, and algal colonies.
2. **Crack Proposals:** Multi-scale directional gradient and dark ridge edge detection on masonry grayscale channels to isolate structural fissures.
3. **Seepage Proposals:** Low-luminance dampness and moisture tide-mark analysis to detect water staining and efflorescence.
4. **Non-Maximum Suppression (NMS):** Class-aware IoU pruning (threshold: 0.40) to eliminate redundant overlapping boxes.

---

## 3. Four Standard Project Classes

| Class ID | Class Name | Visual Definition | Annotation Rule |
|:---:|:---|:---|:---|
| **0** | **Normal** | Undamaged masonry surface, intact heritage carving | **0 defect bounding boxes**. Do NOT draw full-image boxes. |
| **1** | **Crack** | Structural fracture, fissure, or split in stone | Tight box enclosing the fracture line. |
| **2** | **Moss** | Biological growth, lichen, algae on stone/mortar | Box enclosing biological colony cluster. |
| **3** | **Seepage** | Water marks, damp streaks, salt efflorescence | Box enclosing moisture staining boundary. |

---

## 4. Handling of the `Normal` Class

- In object detection, negative samples (healthy stone) must **NOT** have artificial full-image bounding boxes $[0, 0, W, H]$.
- An image depicting intact masonry is saved with **zero bounding boxes** in Pascal VOC XML.
- During SSD training, these images feed into SSD hard negative mining.
- In the review interface, click **Mark Normal (0 boxes)** or press shortcut `N`.

---

## 5. Confidence Policy

- `auto_accept_threshold: 1.0` (Disabled: **No proposal is ever auto-accepted**).
- `review_threshold: 0.50` (Proposals with confidence $\ge 0.50$ are highlighted on the review canvas).
- All generated proposals default to status: `REVIEW_REQUIRED`.

## 7. Step-by-Step Execution Workflow

### Step 1: Install Dependencies
```bash
pip install flask pillow numpy matplotlib pyyaml
```

### Step 2: Generate AI Proposals
Scans the 307 unique images and writes proposals into `ai/annotations/proposals/`:
```bash
python ai/annotation_assistant/propose_annotations.py
```

### Step 3: Launch Human Review Interface
Starts the interactive browser-based review tool:
```bash
python ai/annotation_assistant/review_server.py
```
Open **`http://127.0.0.1:5500`** in Google Chrome or Microsoft Edge.

### Step 4: Reviewing Images in the UI
- **Accept Proposal:** Inspect AI boxes; adjust labels or coordinates if needed.
- **Draw New Box:** Click and drag on the canvas to add a missing defect box.
- **Edit / Move Box:** Click a box to select, move, or change its class via the buttons or dropdown.
- **Delete Box:** Select a box and press `Delete` (or click the `×` button).
- **Mark Normal:** If the image is free of decay, press `N` (records 0 defect boxes).
- **Flag for Review:** If a region is ambiguous, press `F` (logs to `flagged_for_review.csv`).
- **Save & Next:** Press `S` or `D` (or click *Save & Next*). The tool automatically writes the verified JSON to `ai/annotations/review/` AND exports the standard Pascal VOC XML to `ai/annotations/raw/`!

### Step 5: Export Pascal VOC XML (Batch)
If needed, batch export all verified records at any time:
```bash
python ai/annotation_assistant/export_pascal_voc.py
```

### Step 6: Validate Annotations
Run the rigorous integrity checker:
```bash
python scripts/validate_annotations.py
```

### Step 7: Run Quality Control & Dataset Statistics
Audit annotations for anomalies and generate sample visual overlays:
```bash
python ai/annotation_assistant/qc_report.py
```

## 8. Known Limitations & Safe Operation

1. **PyQt Desktop Incompatibility:**  
   Standard `labelImg` crashes on Python 3.13 due to PyQt5 integer/float scaling bugs. The web review server provided here runs natively on Flask with zero Qt dependencies.
2. **False Positives in Heuristic Proposals:**  
   Deep ornamental carvings or cast shadows from temple gopurams may trigger crack proposals. These must be rejected or edited by the human reviewer.
3. **No Training Until Complete:**  
   SSD model training remains completely locked until all 307 images have been reviewed and `scripts/validate_annotations.py` confirms 100% data integrity.
